# T-01 Contracts: card types, vocabulary, config, SQLite store
Wave 0. Depends on: T-00.

## Goal
Implement the card, price record, match result and log record types, the vocab and config loaders, and the SQLite schema in docs/architecture.md.

## Read first
docs/build-requirements.md "Market card and price record", "Decision log"; docs/architecture.md storage schema; ADR-002, ADR-005

## Acceptance criteria
- Payoff fields are optional values; an empty value never equals anything, including another empty (unit test).
- Decimal type: parse from string, normalize with no trailing zeros ("3.50" becomes "3.5"), integer micro-dollar arithmetic, no float64 in the package (test greps source).
- Op type with Complement(): gt<->lte, gte<->lt.
- vocab.yaml loader: lookup of a value not in the vocabulary returns empty (supports test 17).
- equinox.yaml loader: allowed venues, reference_venue, counter_venue, price_max_age.
- SQLite schema created by migration; repositories for raw_responses, cards, prices, fetch_runs, skips, decision_log.
- decision_log repository exposes Append and read methods only; a test asserts no update or delete path exists.
- cycles table (id, kind, started_at, completed_at, status, trigger) and a run lock with acquire, release and refuse-with-reason; readers can query the latest completed cycle.
- equinox.yaml loader also reads the watch and feed sections.
- Validation helpers for inconsistent records: unknown venue, bad side, price outside 0 to 1, unparseable deadline.
