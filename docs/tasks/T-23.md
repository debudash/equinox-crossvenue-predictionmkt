# T-23 Background watch scheduler
Wave 3. Depends on: T-20 (fetch wiring), T-12 (matcher), T-13 (router).

## Goal
Implement amendment A1 and A5: `equinox watch` with a discovery loop, a price loop and retention, in one process holding the run lock.

## Read first
docs/build-requirements.md amendments; ADR-008; docs/architecture.md "Background refresh and feed cache"

## Acceptance criteria
- Intervals from config/equinox.yaml; startup refuses a prices_every that is not below router.price_max_age, naming both values (test W11).
- Runs as its own process; never imports internal/feed.
- Discovery: fetch, then match only if cards were added or changed (test W1).
- Prices: refresh only markets in same or opposite pairs; save a record on every poll (test W2); re-run route only for pairs whose needed price changed, with as_of = refresh time (test W3), for both yes and no (test W9).
- Each pass completes a numbered cycle; a failed pass is marked failed and never shown (supports W5).
- A venue failure in one cycle is saved and counted; the next cycle runs normally (test W4).
- Backoff on rate-limit responses, logged with the wait applied.
- Retention prunes only price records and price raw responses older than retention (test W8).
- Clean shutdown on interrupt releases the run lock.
- Tests use fixtures and an injected clock for the scheduler only; the router still receives as_of and never reads the clock.
